# 燈燈悅心

隨手記一則善行點滴或觀功念恩，一天供一盞燈。
大家的燈飄在同一片夜空，點一盞就看得到那天發生了什麼。

一個沒有建置步驟的 PWA：純 ES modules，丟到任何靜態主機就能跑。

---

## 怎麼運作

### 一則短短的就好

一天最多 **3 則**，類別是標籤不是必填格：

| | |
|---|---|
| 善行點滴 | 再小都算。幫人開個門、忍住一句話，都是。 |
| 觀功念恩 | 看到誰的好，替他高興一下。 |
| 誦經 | 翻幾頁都算，頁數可以留空。 |
| 其他 | 想到什麼寫什麼。 |

**寫一則燈就亮**，只是隨喜了別人的燈也算。門檻刻意壓到最低——
會把人累垮的從來不是「今天沒力氣」，是「今天又沒達標」。

上限 3 則不是為了限制你，是為了讓「一則」還是一件事。
可以無限寫的話，寫下來這個動作就不值錢了。

### 一天一盞燈

算過了。一則一盞的話，200 人 × 3 則 × 3 天 = 一片天空 1800 盞，
畫面糊成一片，而且每一盞就不代表什麼了。
一天一盞，同樣條件最多 600 盞，實際活躍率算三成大概 180 盞，
是一片看得出層次的夜空。

**寫得多不是多幾盞燈，是那一盞比較可能是少見的形制、焰色比較旺。**

燈有四個維度：

| | 幾種 | 由什麼決定 |
|---|---|---|
| 形制 | 20 | 一則一抽，只留比較難得的那盞（運氣） |
| 燈身色 | 11 | 當天哪一類寫得最多（色系）＋ 寫了多少（深淺） |
| 焰色 | 6 | 連續天數優先，其次是當天的份量與隨喜 |
| 紋樣 | 5 | **誰供的**。同一個人永遠同一種紋 |

共 6,600 種組合。

**難得的燈要看得出來。** 共同燈海裡畫得出來的只有一顆光點——顏色是焰色、
大小是稀有度，形制跟燈身色都得點開才看得到。抽到難得卻幾乎看不出來，
那個驚喜就沒有落地。

所以少見的燈會在缽口描一道金，難得的整盞鎏金、連焰心都是金的，
天上那顆光點也跟著鑲一圈金邊。金邊而不是更亮：亮度已經是「很多人隨喜」的意思了，
兩件事用同一個訊號就會分不出來。

金不是第 12 種燈身色——**燈身色仍然由你寫了什麼決定**，金是加在上面的一層。
「顏色是你決定的，形制是運氣」這條沒有被打破，只是運氣現在也看得見了。

紋樣不是抽的，這點很重要：形制和顏色都由當天做了什麼決定，
所以一群人做同樣的事會供出一模一樣的燈。紋樣讓每個人的燈認得出來——
在共同燈海裡點開，一眼就知道是誰的。

### 寫一則，燈就亮了

沒有「供燈」按鈕。寫下第一則的那一刻燈就亮起來，那一下就是開獎。

本來是寫完自己按一下才開獎，結果變成：想多寫幾則再一次供比較划算，
於是一直不按，然後忘記，隔天被系統補供——**最該屬於你的那一下反而是系統按的**。

現在倒過來，**一則一抽**：第一則就把燈供上去，之後每補寫一則就多一次
「再抽一次」的機會，而且**只往上**——抽到比較難得的才換，抽到普通的
就留著現在這盞。

只往上這件事很重要。如果補寫是拿已經到手的燈去賭，就會有人為了不弄丟
難得的燈而不敢再寫，那就本末倒置了。

那天寫幾則，最後拿到的燈大概是什麼（實測 40000 次）：

| 那天寫了 | 常見 | 少見 | 難得 |
|---|---|---|---|
| 1 則 | 61% | 29% | 10% |
| 2 則 | 33% | 45% | 22% |
| 3 則 | 17% | 49% | 34% |

顏色不在這個機制裡，它本來就不是抽的：燈身色與焰色由當天寫了什麼算出來，
所以補寫一則之後它們會當場跟著變。形制才需要自己按那一下。
過了今天，整盞就定下來了。

一天之內寫了三種不同的事（善行／念恩／誦經／其他），燈身會是**泥金**。
連續天數只在**剛好走到倍數那一天**變色：白焰每 7 天、青焰每 21 天、紫焰每 49 天。

不是「連滿 49 天之後每一盞都是紫焰」——那會讓夜空在最該豐富的時候
變成單色，而且那個顏色也不再代表什麼，因為它天天都在。
斷了只是回到藤黃焰，已經供出去的燈不會有任何變化。

所有燈都由 `src/lamp.js` 的參數化 SVG 畫出來，不需要美術素材。
12 形制 × 5 燈身色 × 3 焰色 = 180 種組合，一張圖都不用畫。

### 共同燈海

**一片天空 = 108 盞**（不是幾天）。滿了自動封存，下一盞開新的一片，
可以一片一片往回翻。

為什麼用數量不用時間：時間制的密度會忽高忽低——冷清的一週是空蕩蕩的
天空，熱鬧的一週糊成一片光。數量制永遠剛好，而且「這片天空滿了」是
全群共享的事件，比任意的日期切點有意義。

108 是佛教慣用的數字，也正好落在畫面舒服的密度範圍（40–120 盞：
低於 20 顯得空蕩，高於 150 就糊掉）。

切點由資料庫依排序算出來，不存狀態——既有的燈不用搬家，
也不會有「忘記封存」這種事。

附帶的好處：它給出一個不是排行榜的共同目標，**這片天空 87 / 108**。

### 夜空會長出東西

里程碑不是字而已，每一個都真的讓畫面出現一樣東西。
文案寫什麼就會出現什麼——寫了一行「再 6 盞，燈海起了風」卻什麼都不發生，
等於 app 在承諾一件它不做的事。

景分兩層長。**這一片填了幾盞**：

| 盞數 | 會發生什麼 |
|---|---|
| 7 | 起風，燈開始飄 |
| 21 | 岸邊長出草，偶爾有人走過 |
| 49 | 遠處浮起一座塔，塔上偶爾亮燈 |
| 108 | 天上出現月亮（也就是這片滿了） |

**這個群一共供過幾盞**（跨天空累計，不會因為換新的一片而清空）：

| 盞數 | 會發生什麼 |
|---|---|
| 216 | 有出家人經過，會停下來合掌 |
| 324 | 水上漂起河燈 |
| 540 | 偶爾有一行雁飛過 |
| 1080 | 滿天都是星 |

為什麼要分兩層：**一片天空上限就是 108 盞**，所以只看「這一片」的話，
49 以上幾乎沒東西可長，而 365 的滿天星在群組裡永遠不會出現。
分開之後，每一片還是從空長到滿，而老群的天空看得出資歷。

### 一片換一種底

第 1 片夜空、第 2 片湖面、第 3 片山谷，然後循環。湖面那片的燈在水裡有倒影。

不做成設定：不用 UI、不用權限、不用改資料庫，而且「下一片是什麼」
本身就是把這一片填滿的動力。

真實世界再疊一層上去——月相本來就跟外面同步，現在冬天會飄雪、
清晨天色會轉淡。只做這兩件，再多天空就不是天空了。

點任何一盞燈，看得到那天的紀錄，可以隨喜、可以說一句。
小卡的標題是**那一天**：燈在最上面（它就是那天的樣子），日期用大字，
底下一則善行一張白卡。形制、焰色那些規格不在這裡講——那是開獎那一刻的事，
之後再翻只想知道那天是誰、做了什麼。

**隨喜越多的燈越亮**，會自然把目光帶過去。亮度用開根號做遞減：
0 到 3 個隨喜差很有感，20 到 40 個幾乎看不出來——
它是「那邊有件事值得看」的指引，不是一個藏起來的排行榜。

### 幾個刻意的設計決定

- **沒有排行榜。** 只有大眾合計。比較心對修行社群是有害的。
- **連續天數不會歸零。** 斷了就是那天空著，燈海裡原本的燈照樣亮著。
- **文案避開「獲得／獎勵／解鎖」。** 燈不是獎品，是你自己點的——因果，不是賞罰。
- **隨喜不佔那 3 則的額度。** 那 3 則是你寫下來的，隨喜是你給出去的，不是同一件事。
- **回應限 60 字**，而且限制寫在資料庫的 CHECK 約束裡。這裡不做成討論區。
- **燈亮了還是可以繼續寫，也可以移掉。** 今天之內燈跟著你的紀錄走，過了今天才定。
  移到一則不剩，燈就收回去——打錯字不該變成那天的紀錄。
- **沒有那種會忘記按的按鈕。** 寫下去燈就亮了，不用記得回來供。
- **一個人可以同時在很多群**，寫一次就能同時亮在好幾片天空。

## 先跑起來（單機模式）

不用設定任何東西，直接開一個本機伺服器：

```bash
python -m http.server 8000
```

然後開 http://localhost:8000

> 不能直接用 `file://` 開——ES modules 和 service worker 都需要 http。
>
> 本機開發時 service worker 不會註冊（它是 cache-first，會讓你剛改好的程式看不到）。
> 要測離線行為的話，把 `src/app.js` 裡的 `isLocal` 判斷暫時拿掉。

這個模式下所有紀錄存在瀏覽器的 localStorage，換裝置要用「我 → 備份」匯出匯入。

## 開群組功能（Supabase）

### 1. 建專案

到 [supabase.com](https://supabase.com) 開一個免費專案。

### 2. 打開匿名登入

Dashboard → **Authentication → Sign In / Providers** →
往下捲到 **User Signups** 那一區 → 打開 **Allow anonymous sign-ins**。

直達網址：`https://supabase.com/dashboard/project/<Project ID>/auth/providers`

這個 app 不用 email 密碼，一個裝置一組匿名身分。
沒開的話 app 會一直拿到 `Anonymous sign-ins are disabled`。

### 3. 建表與權限

Dashboard → **SQL Editor**，把 [`supabase/schema.sql`](supabase/schema.sql) 整份貼上執行。

資料模型的核心是**燈屬於人，不屬於群**：

```
lamps        你的燈（每人每天一盞）
lamp_shares  這盞燈分享到哪幾個群
```

所以一個人可以同時在很多群裡，寫一次就能同時亮在好幾片共同燈海。
取消分享到某個群，只是把那筆 share 拿掉，你自己的燈還在。

權限的原則是**什麼都看不到是預設**，要看得到必須證明你跟對方在同一個群組，
而且判斷全部在資料庫做，不靠前端擋。

### 4. 填設定

Dashboard → **Project Settings → API Keys**（新版介面改名了，不叫 API）：

```js
export const SUPABASE_URL = 'https://<Project ID>.supabase.co';
export const SUPABASE_PUBLISHABLE_KEY = 'sb_publishable_...';
```

- **Project URL** 在 Settings → General，是 `https://<Project ID>.supabase.co`
- **Publishable key** 就是 `sb_publishable_...`（舊版叫 anon key，
  是一長串 `eyJhbG...` 的 JWT，也還能用，但 Supabase 正在淘汰）

這把金鑰本來就是公開的（它靠 RLS 擋權限，不是靠保密），commit 進 git 沒問題。

**`sb_secret_...`（舊名 service_role）永遠不要放進前端**——它繞過所有 RLS，
在同一頁上就在這把的下面，長得很像，別拿錯。

### 5. 開群、發邀請碼

App 裡 → 同行分頁 → 右上角 → 「開一個新群」。

會拿到一組 8 碼邀請碼（已排除容易看錯的 0/O/1/I）。
把碼給想找來的人，他們在同一個地方貼上就能加入。

> 誰有碼誰就進得來，不要貼在公開的地方。

### 群組人數與管理

預設上限 **200 人**（`groups.max_members`，開群的人可以在資料庫改，最高 2000）。

人一多就需要最起碼的管理手段，schema 裡已經有：

- 群主可以把某盞燈從自己的群移掉（`lamp_shares` 的 delete policy）
- 群主可以請人離開（`group_members` 的 delete policy）
- 燈的主人可以刪掉自己燈上不想要的回應

這些目前只有資料庫權限，**還沒做 UI**。200 人的群上線前建議先補上，
不然出事只能進 Supabase Dashboard 手動處理。

## ⚠️ 上線前一定要做的一件事

`src/quotes.js` 分成兩層，**不要混在一起**：

- **`VOICES`** — 五個角色自己的話，**共 100 句**。不引用任何人，怎麼寫都不會出事。

  | 角色 | 語氣 | 句數 |
  |---|---|---|
  | 燈童 | 溫暖、直接。陪你的那個。 | 20 |
  | 掃地的 | 短、務實、帶點自嘲。做事的人的語氣。 | 20 |
  | 寺裡的貓 | 慵懶、吐槽。你太用力的時候讓你鬆下來。 | 20 |
  | 門口的石獅 | 話少、時間尺度大。你急的時候牠不急。 | 20 |
  | 池裡的蓮 | 緩慢，講生長。看不出進度的日子是牠的。 | 20 |

  每天輪一位，會避開前一天講話的那位。五個都是虛構的東西——
  燈、掃地的、貓、石獅、蓮花——所以不會冒名任何真實存在的人。

  要加句子就往對應角色底下加，但先讀幾句原本的抓語氣：
  五種聲音混在一起就沒意思了。
- **`QUOTES`** — 有出處的引文。**每一條都必須對原典核過才能上線。**

目前 `QUOTES` 裡每一條都標著 `verified: false`，UI 只會顯示 `verified === true` 的，
所以現在開獎卡上只會出現燈童自己的話，不會出現任何引文。

逐句對過原文之後，把該條改成 `verified: true` 並填上 `checkedAt`。

**絕對不要讓 AI 生成「佛陀說」「祖師說」的句子填進 `QUOTES`。**
編造法語就是妄語，而且朋友之間傳開了收不回來。寧可只有十句真的，不要一百句假的。

（這也是為什麼「燈童」是個虛構角色，牠是「捎來一句」，不是「說」。）

## 部署

沒有建置步驟，整個資料夾就是網站。

- **GitHub Pages**：push 上去，Settings → Pages → 選 branch，完成
- **Netlify / Cloudflare Pages**：拖資料夾進去就好，build command 留空

改完程式記得把 `sw.js` 裡的 `VERSION` 加一，不然使用者拿到的還是舊快取。

## 可以調的參數

都在 `src/config.js`：

| | 預設 | |
|---|---|---|
| `MAX_ENTRIES_PER_DAY` | 3 | 一天最多寫幾則 |
| `SKY_SIZE` | 108 | 一片天空幾盞，滿了就換新的一片 |
| `SKY_RENDER_CAP` | 150 | 一片天空最多畫幾盞，超過的據實說 |
| `MONTHLY_GOAL` | 500 | 本月大眾共修目標（頁） |
| `DEFAULT_SUTRA` | 大般若經 | |
